## Однозначні помилки (виправте їх перед співбесідою)

| Q | Конспект | Правильна відповідь | ID |
|---|---|---|---|
| Q9 | «methods available in **storing** sequential files» | Питання про **сортування** послідовних файлів (зовнішнє сортування): straight merging, natural merging, polyphase sort, distribution of initial runs | P6-35 |

## Неточності, на яких «ловлять»

| Q | Що не так | ID |
|---|---|---|
| Q3 | «RDBMS = array of structures» — завчена відповідь на логічному рівні. Реальні СУБД використовують B+-дерева і хеш-індекси | P6-32 |
| Q4 | «для списку з різнотипними даними звичайний вказівник неможливий, потрібен void pointer» — посилання можна лишити типізованими (`struct node *`), `void *` чи `union` потрібні лише для **даних** | P6-33 |
| Q5 | «пріоритетній черзі потрібні **дві** черги» — фольклор; стандартна реалізація — купа, без черг узагалі | P6-34 |
| Q10 | «за способом зберігання зв'язний список нелінійний» — лінійність є логічною властивістю; Q43 конспекту сам називає список лінійним | P6-36 |
| Q13 | «linear search: O(n) порівнянь у будь-якому випадку» — best case Θ(1) (знайдено першим), average/worst Θ(n) | P6-39 |
| Q15 | «в постфіксній нотації дужки не потрібні» — тільки якщо арність кожного оператора фіксована (унарний мінус ламає це) | P6-40 |
| Q19 | AVL: «pivotal value or height factor» — правильно **balance factor**; перебалансування при ±2 | P6-41 |
| Q20 | чому B+-дерево для індексів: не згадано головне — великий fan-out (менша висота → менше читань диска) і зв'язані листя (діапазонні запити) | P6-42 |
| Q23 | «node class» — це визначення з дизайну класів C++ (Stroustrup, TC++PL 3rd ed. §25.4), а не DSA-поняття вузла (дані + посилання) | P6-44 |
| Q27, Q28 | дублікати Q7 і Q16 | P6-46 |
| Q29 | malloc vs calloc: не сказано, що `malloc` **не ініціалізує** пам'ять, а `calloc(nmemb, size)` обнуляє її (поширені реалізації — glibc, macOS libmalloc — також повертають NULL при переповненні nmemb·size) | P6-47 |
| Q31 | `front = (front + 1) % size` подано як загальне правило; це лише просування front при dequeue в кільцевій черзі | P6-49 |
| Q35 | «isEmpty() перевіряє, чи є хоча б один елемент» — навпаки: повертає true, коли елементів **немає** | P6-50 |
| Q37 | «push is the direction» — push є операцією, а не напрямом | P6-51 |
| Q40 | вказівник названо структурою даних | P6-53 |
| Q42 | стек і черга названі динамічними — це залежить від реалізації (стек із coding question 3 статичний) | P6-54 |
| Q44 | загальні графи «ієрархічні» — ні, ієрархічні лише дерева | P6-55 |
