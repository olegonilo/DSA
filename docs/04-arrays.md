## Формула адреси — у конспекті з помилкою знака

Конспект, p.25 (P2-24):

> Byte address of element A[i] = base address + size * (**first − index**)

Правильно:

$$\text{addr}(A[i]) = BA + \text{size} \cdot (i - LB)$$

де LB — нижня межа індексу. Перевірка на власному прикладі конспекту (p.26): BA = 999, size = 2,
LB = −1, i = 8 → 999 + 2·(8 − (−1)) = **1017**. Конспект у прикладі рахує правильно (через i − LB),
тобто формула і приклад суперечать одне одному. У C LB = 0 завжди: `&a[i] == (char*)a + i*sizeof a[0]`.

### Двовимірні масиви (C — row-major)

```
int a[m][n];       рядок 0            рядок 1            рядок 2
пам'ять:     [a00 a01 a02 a03][a10 a11 a12 a13][a20 a21 a22 a23]
row-major:    addr(a[i][j]) = BA + (i·n + j)·size        ← так розміщує C (C11 6.5.2.1p3)
column-major: addr(a[i][j]) = BA + (j·m + i)·size        ← Fortran, MATLAB
```

Діаграми конспекту використовують індекси з 1 (a11…a33), а формули — з 0 (P2-31). У формулі column-major
дужка стоїть не на місці й «ковтає» знак `=` (P2-32). Обидві формули вище наведені в правильному вигляді.

## Код з конспекту, що не компілюється (p.23–24)

```c
void main            // P2-18: немає (), clang: variable has incomplete type 'void'
{
int marks_1 = 56; marks_2 = 78, marks_3 = 89;   // P2-14: ';' після 56 → marks_2/3 не оголошені
Float avg = (marks_1 + marks_2 + marks_3)/3;    // P2-15: Float; P2-16: ЦІЛОЧИСЕЛЬНЕ ділення 223/3 = 74
print(avg);                                     // P2-17: в C немає print
```

Друга версія (з масивом) **ніколи не ділить на 3**: друкує суму (P2-20) і читає неініціалізований
`float avg` (P2-19, UB). Правильно:

```c
int main(void) {
    int marks[3] = {56, 78, 89};
    float sum = 0.0f;
    for (int i = 0; i < 3; i++) sum += marks[i];
    printf("%.2f\n", sum / 3);   // 74.33, а не 74
    return 0;
}
```

## Складність операцій (уточнена)

| Операція | Конспект | Точно |
|---|---|---|
| Доступ за індексом | O(1) | Θ(1) |
| Пошук | O(n) | Θ(n) лінійний; **Θ(log n)** якщо масив відсортований (див. [10-searching](10-searching.md)) |
| Вставка / видалення | O(n) | Θ(n) у середині; **Θ(1)** в кінці (амортизовано для динамічного масиву) |

## Експеримент: «O(n) обхід» масиву проти зв'язного списку

![traverse](../charts/traverse.png)

`bench_ds` → `results/traverse.csv`. Сума всіх елементів, нс на елемент:

| n | масив | список, вузли підряд | список, вузли перемішані |
|---|---|---|---|
| 1 024 | 0.081 | 1.44 | 1.45 |
| 65 536 | 0.053 | 1.01 | 8.11 |
| 16 777 216 | 0.044 | 0.74 | **111.3** |

Обсяг структури: масив 4n Б, список 16n Б (вузол = int + padding + вказівник). Кожен вимір триває
щонайменше 100 мкс: внутрішній прохід повторюється, бо тік таймера 41.7 нс.

Асимптотично всі три — Θ(n). Фактично при n = 2²⁴ різниця **2 500×** (111.3 / 0.0438; у попередньому прогоні — 2 800×, бо масив
давав 0.040 нс/елем — для такої швидкої операції розкид між прогонами ±10 %):

- масив: послідовний доступ; компілятор векторизує суму (в асемблері `bench_ds` — SIMD-інструкції `saddw.2d`/`saddw2.2d`), апаратний prefetcher вгадує адреси;
- список з вузлами підряд: кожен крок чекає на завантаження `p->next` (залежність по даних),
  але адреси послідовні — prefetcher встигає;
- перемішаний список: кожен `p->next` — випадкова адреса. Поки 16·n Б ≤ L2 (16 МБ), крок коштує 6–12 нс;
  коли структура в рази більша за L2 — 111.3 нс на крок, тобто кожен крок стає повною затримкою
  доступу до DRAM (лічильниками кешу не підтверджено, див. [методику](00-methodology.md)). Це і є «pointer chasing».
  На графіку видно, що злами кривої перемішаного списку припадають **рівно** на межі L1d (128 КБ: 1.16 → 6.18 нс)
  і L2 (16 МБ: 12.3 → 36.6 нс), якщо по осі X відкладати реальний обсяг структури (16 Б на вузол).
  Це найсильніший доказ кеш-пояснення, доступний без апаратних лічильників.

**Висновок для практики:** список виграє, тільки коли потрібні O(1) вставки/видалення за відомим вузлом.
