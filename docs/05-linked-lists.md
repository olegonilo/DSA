```
Однозв'язний:      head → [10|•] → [20|•] → [30|∅]
Двозв'язний:       head → [∅|10|•] ⇄ [•|20|•] ⇄ [•|30|∅]
Кільцевий:         head → [10|•] → [20|•] → [30|•] ─┐
                            ▲───────────────────────┘
Двозв'язний кільцевий: prev першого = останній, next останнього = перший; NULL немає ніде (P2-38)
```

## Критична помилка: `malloc(sizeof(struct node *))`

Конспект, p.34 (P2-40):

```c
ptr = (struct node *) malloc(sizeof(struct node *)     // так у конспекті (ще й без ')' і ';')
```

`sizeof(struct node *)` — розмір **вказівника** (8 Б), а не вузла (16 Б: 4 int + 4 padding + 8 вказівник).
Запис `ptr->next = …` пише за межі блоку. Це реальне переповнення купи; `make experiments` → `ex_ub_malloc_sizeof_pointer`:

```
sizeof(struct node *) = 8, sizeof(struct node) = 16, offsetof(next) = 8
1) код з конспекту: malloc(sizeof(struct node *))
      | ERROR: AddressSanitizer: heap-buffer-overflow on address 0x602000000998
      | WRITE of size 8 at 0x602000000998 thread T0
      | 0x602000000998 is located 0 bytes after 8-byte region [0x602000000990,0x602000000998)
   [конспект] дочірній процес вбито сигналом 6 (Abort trap: 6)
2) виправлено: malloc(sizeof *ptr)
   [виправлено] дочірній процес завершився з кодом 0
```

**Ідіома, що виключає цю помилку:** `ptr = malloc(sizeof *ptr);` — тип береться з самої змінної.
Плюс перевірка на `NULL` (у конспекті її немає ніде).

Також: 4 визначення `struct node {...}` на p.31–33 не мають `;` після `}` (P2-35) — clang: `expected ';' after struct`.

## Складність — уточнення до таблиці конспекту

Конспект (p.34) пише O(1) для вставки й видалення в однозв'язному списку у всіх випадках (P2-39).

| Операція | Однозв'язний (head) | Однозв'язний (head+tail) | Двозв'язний |
|---|---|---|---|
| вставка на початок | Θ(1) | Θ(1) | Θ(1) |
| вставка в кінець | **Θ(n)** | Θ(1) (`sll_push_back`) | Θ(1) |
| вставка на позицію k | Θ(k) — пошук місця | Θ(k) | Θ(k) |
| видалення першого | Θ(1) | Θ(1) | Θ(1) |
| видалення останнього | Θ(n) | **Θ(n)** — потрібен передостанній | Θ(1) (`dll_pop_back`) |
| видалення відомого вузла | Θ(n) — потрібен попередник | Θ(n) | **Θ(1)** (`dll_unlink`) |
| пошук | Θ(n) | Θ(n) | Θ(n) |

O(1) — тільки на голові або коли попередник **вже відомий**.

## Випадки видалення

Конспект: «The list can either be empty or full» (P2-42) — **у зв'язного списку немає стану «повний»**.
Правильні випадки: (1) порожній, (2) один вузол — оновлюються і `head`, і `tail`,
(3) більше одного вузла. `sll_remove_value` обробляє їх одним кодом через вказівник на вказівник:

```c
sll_node **pp = &l->head, *prev = NULL;
while (*pp && (*pp)->data != v) { prev = *pp; pp = &(*pp)->next; }
if (!*pp) return -1;
sll_node *dead = *pp;
*pp = dead->next;                 // працює і для голови, і для середини
if (l->tail == dead) l->tail = prev;
free(dead);
```

## Класичні прийоми (реалізовано і протестовано)

| Прийом | Функція | Ідея |
|---|---|---|
| Розворот за O(1) пам'яті | `sll_reverse` | три вказівники prev/cur/next |
| Пошук циклу (Флойд) | `sll_has_cycle` | повільний +1, швидкий +2; зустрінуться, якщо є цикл |
| Середина за 1 прохід | `sll_middle` | швидкий доходить до кінця, коли повільний — у середині |
| Задача Йосипа Флавія | `josephus_cll` | кільцевий список; перевірено J(41,3) = 31, J(7,3) = 4 |

Інтерв'ю-питання Q22 у конспекті («як перевірити, що список кільцевий») містить код, що **розіменовує NULL**
на некільцевому списку і помилково каже «circular» для списку з одного вузла (P6-43). Правильна відповідь:
`sll_has_cycle` (умова `fast && fast->next`).
